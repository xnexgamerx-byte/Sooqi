# سوقنا

تطبيق إعلانات مبوّبة للسوق العراقي: سيارات، عقارات، موبايلات، وكل ما يُباع ويُشترى.

- **الخطة الكاملة:** [`docs/plan.html`](docs/plan.html) — النطاق، البنية، التكاليف، الاستضافة، الترويج
- **تصاميم الشاشات:** [`docs/screens.html`](docs/screens.html) — إحدى عشرة شاشة
- **صور الأقسام:** [`assets/README.md`](assets/README.md) — تصديرها من Figma

النسخة الأولى تُطلق بقسمين مفعّلين فقط، **السيارات والموبايلات**، وفي بغداد.
بقية الأقسام موجودة في القاعدة وتظهر في الشبكة بحالة «قريباً». السبب في
القسم الأول من الخطة.

## التشغيل

```bash
pnpm install
cp .env.example .env          # عبّئ DATABASE_URL
pnpm db:push                  # ينشئ الجداول
pnpm db:seed                  # يزرع 19 محافظة و 31 قسماً
psql "$DATABASE_URL" -f packages/db/sql/001_search.sql
pnpm dev                      # الخادم على المنفذ 5000
```

| الأمر | ما يفعله |
| --- | --- |
| `pnpm dev` | يشغّل الخادم مع إعادة التحميل |
| `pnpm typecheck` | فحص الأنواع عبر كل الحزم |
| `pnpm db:push` | يدفع تغييرات المخطط إلى القاعدة (تطوير فقط) |
| `pnpm db:generate` | يولّد ملف ترحيل بدل الدفع المباشر |
| `pnpm db:seed` | يزرع المدن والأقسام، آمن للتكرار |

## البنية

```
packages/db       مخطط Drizzle + بذور المدن والأقسام + فهارس البحث
packages/server   واجهة Fastify
docs/             الخطة والتصاميم
assets/           صور الأقسام ومانيفست تصديرها من Figma
```

- **قاعدة البيانات:** PostgreSQL مع Drizzle ORM
- **الخادم:** Node 22 و Fastify 5 و Zod
- **البحث:** `pg_trgm` المدمج. لا تضف Meilisearch قبل أن يبطؤ هذا فعلاً
- **الصور:** Cloudflare R2. نخزّن المفتاح لا الرابط الكامل، فالنطاق يتغير والمفتاح لا

## الواجهة

| المسار | الوصف |
| --- | --- |
| `GET /health` | فحص الحياة |
| `GET /api/categories` | شجرة الأقسام كاملة، مع المعطّلة |
| `GET /api/categories/roots` | أقسام الجذر فقط، لشبكة الشاشة الأولى |
| `GET /api/categories/postable` | الأقسام المفتوحة للنشر |
| `GET /api/categories/:slug/fields` | الحقول الديناميكية للقسم |
| `GET /api/cities` | المحافظات مع مناطقها |
| `GET /api/listings` | التصفّح مع الفلاتر والترقيم |
| `GET /api/listings/:id` | تفاصيل إعلان |
| `POST /api/listings/:id/phone` | كشف رقم البائع، ويُسجَّل |
| `GET /api/me/listings` | إعلاناتي |
| `POST /api/listings` | إنشاء مسودة |
| `PATCH /api/listings/:id` | تعديل |
| `POST /api/listings/:id/publish` | نشر، يتحقق من الحدّ والصور |

فلاتر التصفّح: `category` و `city` و `minPrice` و `maxPrice` و `condition`
و `q` و `sort` (`recent` أو `cheap` أو `expensive`).

الترتيب `recent` يستخدم مؤشراً (`cursor`) لا إزاحة، لأن الإزاحة تكرّر
الصفوف حين ينشر أحدهم إعلاناً أثناء تمرير المستخدم. ترتيبا السعر
يستخدمان `offset`.

## قرارات مقصودة

**رقم الهاتف لا يظهر في نص الصفحة.** يُجلب بضغطة على `/listings/:id/phone`،
وكل ضغطة تُسجَّل مع بصمة زائر مُجزّأة. هذا يمنع كشط الأرقام بالجملة.

**النشر يضع الحالة `pending` لا `published`.** المراجعة اليدوية مفعّلة في
أول ثلاثين يوماً. عطّلها بتغيير سطر واحد في `routes/listings.ts` حين تثق
بحجم البلاغات.

**حالات الإعلان سبع من اليوم الأول**: مسودة، بانتظار المراجعة، منشور،
مرفوض، منتهٍ، مباع، محذوف. إضافة حالة لاحقاً تعني لمس كل استعلام.

**جداول المحفظة والتمييز موجودة وفارغة.** التطبيق مجاني بالكامل الآن،
لكن وجود الجداول يعني ألا نهاجر بيانات حين يُفعَّل الدفع.

## تنبيه أمني

`DEV_AUTH=1` يقبل ترويسة `x-user-id` بدل تسجيل دخول حقيقي، ويسمح لأي أحد
بانتحال أي حساب. الخادم **يرفض الإقلاع** إذا وجدها مفعّلة مع
`NODE_ENV=production`. لا تعطّل هذا الفحص.
